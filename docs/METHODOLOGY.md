# 方法与来源

## 证据范围

这份整理基于同一来源设备导出的三个内置应用，研究对象以包名、版本、大小和 APK SHA-256 确定。本文的行为描述对应静态代码中的实现路径。

资料来源包括三个原始逆向分析会话及其落盘报告、两个后续复核聊天及其代码核验结果。公开包以文档角色记录来源：

| 来源 | 研究对象 | 纳入的产物 |
|---|---|---|
| 原始分析 A | SystemHelper | 总报告、四份专项和关键 smali/Manifest |
| 原始分析 B | GuardProvider | 总报告、五份专项、关键 Java/Manifest |
| 原始分析 C | MIUI 安全中心 | 总报告、七份专项、独立隐私复核、关键 Java/XML、离线解析工具 |
| 后续复核 | 字段赋值、上传调用、权限及同意流程 | 各应用最终报告及总数据流表中的纠错 |

原始会话与手机日志保存在来源环境；公开资料采用脱敏报告与精选代码证据。

## 结论如何关联到证据

优先从数据读取 API 出发，追踪赋值与摘要处理、请求对象构造、发送调用、业务入口和开关。一个接口名或方法名的含义，以调用及赋值代码解释。

证据索引分别位于 [SystemHelper](../apps/systemhelper/evidence-index.json)、[GuardProvider](../apps/guardprovider/evidence-index.json) 和 [安全中心](../apps/securitycenter/evidence/index.json)。证据文本保存原行号，并用 SHA-256 标识对应文件；阅读报告中的相对链接可直接到达随包证据。原工具生成的 REA Evidence ID 作为历史取证索引保留，随包文本和文件摘要提供可离线核对的材料。

## 采用的字段纠正

| 对象 | 本次采用的准确表述 |
|---|---|
| SystemHelper 注册体 | JSON 经 AES 处理后通过 HTTP 发送 |
| SystemHelper 应用清单 | 来源为 UsageStats 记录，默认时间窗口为 7 天 |
| GuardProvider OneTrack | IMEI/IMSI 路径先读标识、再生成 MD5 列表，并经过区域/配置等门控 |
| 安全中心应用清单 | 当前可枚举的非系统应用包名/版本，由检测页面任务组装 |
| 安全中心流量 `imei` | Android ID 加业务常量后派生的 MD5 |
| 安全中心校准短信 | 告知弹窗确认后提交；号码处理中包含字符遮罩 |
| 安全中心报警辅助 | 按 HTTP/SMS 两条路径说明 AES/RSA 处理及位置共享 |
| 安全中心 FBO | 写入本机配置并交给系统服务 |

## 文件组织

`REPORT.md` 与安全中心 `REVIEW.md` 提供整理后的叙述。`SOURCE_REPORT.md`、`archival/` 保存脱敏后的历史分析文本及其警示，适合追溯分析过程。历史文本按原记录保留，引用结论时以本次报告和对应代码为准。

各目录只发布研究相关的文本产物。样本二进制以摘要和大小定位；完整反编译树在本地保留，公开包选择支撑数据流结论的文件。
